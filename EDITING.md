# Как править сайт Neoscholia

Сайт статический. Всё его содержимое — файлы в этом репозитории. Правка = изменить файл и сохранить (commit) в ветку `main`. Через 1–2 минуты GitHub сам соберёт сайт и выложит новую версию. Каждая правка остаётся в истории: на каждой странице внизу есть ссылка «история правок».

## Где что лежит

| Что | Где |
|---|---|
| Страницы | `src/*.njk`: `index` (главная), `alexander`, `scholia`, `music`, `odyssey-10`, `method`, `studies`, `about`, `study-laestrygonians` |
| Шапка, подвал, общий каркас | `src/_includes/header.njk`, `footer.njk`, `layouts/base.njk` |
| Пункты меню, адрес репозитория | `src/_data/site.json` |
| Ступени статусов (тексты, статьи) | `src/_data/ladders.yaml` |
| Список работ на странице «Исследования» | `src/_data/studies.yaml` |
| Стили: общие / отдельной страницы | `src/assets/css/base.css` / `src/assets/css/pages/<страница>.css` |
| Скрипты страниц | `src/assets/js/<страница>.js` |
| Шрифты (лежат на самом сайте) | `src/assets/fonts/` — пересобираются командой `node scripts/vendor-fonts.mjs` |
| Материалы исследований | `research/` (досье статьи публикуется рядом с ней) |
| Старые макеты-артефакты (архив) | `design/` — на сайт не влияют |

Каждая страница начинается с шапки между двумя строками `---` (front matter):

```yaml
---
title: "Схолии к «Одиссее» X"   # заголовок вкладки браузера
nav: "library"                  # какой пункт меню подсвечен: library | studies | method | about
permalink: "odyssey-10.html"    # адрес страницы
ladder: "text"                  # лестница статусов (для текстов и статей)
status: "models"                # текущая ступень
version: "0.1"
updated: "25.10.2026"
mock: "<b>Макет страницы.</b> …" # жёлтый баннер сверху; удалите строку — баннер исчезнет
---
```

## Частые правки

**Поправить слово или фразу.** Найдите текст в `src/<страница>.njk` (поиск по файлу), исправьте, сохраните. Текст страницы — обычный HTML.

**Переключить статус.** Поменяйте одно слово в `status:` в шапке страницы:
- тексты: `draft` → `models` → `editor` → `review` → `final`;
- статьи: `dossier` → `preprint` → `author` → `review` → `final`.

Подписи ступеней, а также новые ступени — в `src/_data/ladders.yaml`. Если в `status` опечатка, сборка остановится и подскажет допустимые значения.

**Обновить версию и дату.** Поля `version:` и `updated:` в шапке страницы.

**Добавить или изменить работу на странице «Исследования».** Отредактируйте `src/_data/studies.yaml` — одна запись на работу. Поля описаны в начале файла.

**Добавить ссылку.** Внутренние ссылки — просто имя файла: `<a href="method.html#ai">`. Внешние — полный адрес.

**Убрать баннер «Макет».** Удалите строку `mock:` в шапке страницы.

## Как сохранять правки

**Прямо в браузере.** Откройте файл на github.com → значок карандаша (Edit) → правка → **Commit changes** в `main`. Для нескольких файлов сразу нажмите `.` на странице репозитория: откроется редактор github.dev, там правки сохраняются одним коммитом.

**На своём компьютере.**

```bash
npm install
```

Предпросмотр с автообновлением, http://localhost:8080:

```bash
npm run serve
```

Затем сохраните правку и отправьте на GitHub:

```bash
git commit -am "Опечатка на странице «Метод»"
```

```bash
git push
```

Проверить сборку локально:

```bash
npm run build
```

```bash
npm run check
```

Сайт собирается в папку `site/`. Её можно открыть и прямо с диска: все ссылки относительные.

Сообщение коммита — это запись в публичной истории правок страницы. Пишите его по-человечески: «Исправлена дата в примечании 17», «Статус статьи: проверено автором».

## Выкладка

`.github/workflows/deploy.yml` на каждый коммит в `main`:
1. собирает сайт;
2. проверяет все внутренние ссылки и якоря — при ошибке ничего не выкладывается;
3. публикует на **GitHub Pages**;
4. если настроено зеркало, копирует то же самое на него.

Ход сборки виден во вкладке **Actions** репозитория.

## Зеркало

Нужно для читателей, у которых GitHub или Cloudflare работают плохо. Подойдёт любой сервер с SSH и веб-сервером (nginx, Caddy), раздающим папку. Cloudflare перед зеркалом не ставить: из России его трафик режется.

В репозитории: **Settings → Secrets and variables → Actions**.
- Variables:
  - `MIRROR_HOST` — адрес сервера;
  - `MIRROR_USER` — пользователь;
  - `MIRROR_PATH` — папка, которую раздаёт веб-сервер, например `/var/www/neoscholia`;
  - `MIRROR_PORT` — если SSH не на 22.
- Secrets: `MIRROR_SSH_KEY` — приватный ключ, чей публичный ключ добавлен в `~/.ssh/authorized_keys` на сервере.

Пока `MIRROR_HOST` не задан, шаг зеркала пропускается. Второе зеркало добавляется копией задания `mirror` с другими переменными.
