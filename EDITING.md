# Как править сайт Neoscholia

Сайт статический. Всё его содержимое — файлы в этом репозитории. Правка = изменить файл и сохранить (commit) в ветку `main`. Через 1–2 минуты GitHub сам соберёт сайт и выложит новую версию. Каждая правка остаётся в истории: на каждой странице внизу есть ссылка «история правок».

## Где что лежит

| Что | Где |
|---|---|
| Страницы | `src/*.njk` — у каждой страницы шапка (front matter) и содержимое |
| Каркас, шапка, подвал | `src/_includes/layouts/base.njk`, `header.njk`, `footer.njk` |
| Общие блоки (макросы) | `src/_includes/ui.njk` — заголовок раздела, лестница статусов, блок статуса, фильтры, оглавление, цитирование и др. |
| Страница перевода | `src/_includes/text-body.njk` + данные текста `src/_data/texts/<ключ>.json` |
| Страница схолий | `src/odyssey-10.njk` + данные `src/_data/scholia/odyssey-10.json`; общие детали страниц чтения — `src/_includes/reader/parts.njk` |
| Текст статьи | `research/studies/<статья>/article.md` (размечает `lib/article.js`); страница `src/study-<статья>.njk` — шапка, сведения о работе, журнал рецензии; особые блоки — `src/_includes/study/` |
| Страница раздела библиотеки | `src/_includes/section-body.njk` + данные раздела `src/_data/catalogue/<раздел>.yaml` (поля описаны в `README.md` там же) |
| Особые блоки разделов (рисунки, таблицы) | `src/_includes/sections/` |
| Реестр разделов и полки «Библиотеки» | `src/_data/sections.yaml` |
| Пункты меню, адрес сайта и репозитория | `src/_data/site.json` |
| Ступени статусов и что они значат | `src/_data/ladders.yaml` |
| Список работ на странице «Исследования» | `src/_data/studies.yaml`; названия разделов и видов работ — `src/_data/studyLists.yaml` |
| Указатели | `src/_data/indexes.json` — пишет `scripts/build-indexes.py`, руками не править |
| Новости для «Истории изменений» | `src/_data/news.yaml` |
| Стили | `src/assets/css/`: `base.css` (цвета, шрифты, кегли, каркас) → `components.css` (общие детали) → `layouts/<тип>.css` (тип страницы) → `pages/<страница>.css` (только особое) |
| Скрипты | `src/assets/js/site.js` — общий для всех страниц; `reader.js` и `article.js` — страницы чтения и статьи (подключаются сами по `pageType`); рядом — скрипты отдельных страниц (рисунок статьи) |
| Шрифты (лежат на самом сайте) | `src/assets/fonts/` — пересобираются командой `node scripts/vendor-fonts.mjs` |
| Материалы исследований | `research/` (досье статьи публикуется рядом с ней) |
| Старые макеты-артефакты (архив) | `design/` — на сайт не влияют |

Основные детали оформления с образцами разметки собраны на странице **«Оформление»** (`styleguide.html`, ссылка в самом низу каждой страницы). Новая страница складывается из этих деталей; новый стиль заводится, только если подходящей детали нет.

## Шапка страницы (front matter)

Каждая страница начинается с шапки между двумя строками `---`:

```yaml
---
title: "Схолии к «Одиссее» X"   # заголовок вкладки; « — Neoscholia» добавится само
description: "…"                # одно предложение для поисковиков и ссылок (необязательно)
nav: "library"                  # какой пункт меню подсвечен: home | library | studies | indexes | method | about
permalink: "odyssey-10.html"    # адрес страницы
pageType: "reader"              # тип страницы: catalogue (раздел) | reader (перевод) | article (статья);
                                # подключает стили этого типа, а у reader и article — и его скрипт
crumbs:                         # «хлебные крошки»; у последнего пункта адрес не нужен
  - { label: "Библиотека", href: "library.html" }
  - { label: "Схолии", href: "scholia.html" }
  - { label: "Песнь X" }
ladder: "text"                  # лестница статусов (для текстов и статей)
status: "models"                # текущая ступень
version: "0.2"
updated: "25.10.2026"
mock: "<b>Версия {version:odyssey-10}.</b> …"   # оговорка редакции: у текстов и статей стоит в блоке статуса под заголовком,
                                # у остальных страниц — полоса под шапкой; удалите строку — она исчезнет
styles: ["…"]                   # особые стили страницы из assets/css/pages/ (обычно не нужны)
scripts: ["…"]                  # особые скрипты страницы из assets/js/ (обычно не нужны)
---
```

Страницы из главного меню «крошек» не имеют; у вложенных страниц цепочка начинается с раздела меню, а последний пункт — сама страница.

## Частые правки

**Поправить слово или фразу.** Найдите текст поиском по папкам `src/` и `research/studies/`: он лежит либо в `src/<страница>.njk`, либо в данных — `src/_data/catalogue/<раздел>.yaml` (страницы разделов), `src/_data/texts/<ключ>.json` (переводы), `src/_data/scholia/<ключ>.json` (схолии), `src/_data/sections.yaml` (полки «Библиотеки»), `src/_data/studies.yaml` (список работ); текст статьи — в `research/studies/<статья>/article.md`. Файл `src/_data/indexes.json` не правьте: его пересобирает скрипт. Текст страниц — обычный HTML.

**Переключить статус.** Поменяйте одно слово в `status:` в шапке страницы:
- тексты: `draft` → `models` → `editor` → `review` → `final`;
- статьи: `dossier` → `preprint` → `author` → `review` → `final`.

Подписи ступеней и фразы «на что можно опираться» — в `src/_data/ladders.yaml`: они показываются под заголовком каждого текста и на странице «Метод». Если в `status` опечатка, сборка остановится и подскажет допустимые значения.

**Обновить версию и дату.** Поля `version:` и `updated:` в шапке страницы и новая запись в начале списка `versions` (у `odyssey-10` и статьи — в шапке страницы, у текстов из данных — в `src/_data/texts/<ключ>.json`): из него строятся «История изменений» и блок «Версии». Если запись забыть, сборка остановится и скажет об этом. Текст `mock` перепишите под новую версию. В остальных местах номер подставляется сам: в данных и в `mock` вместо числа пишется `{version:имя-страницы}`, например `версия {version:zacher-1}`.

**Добавить текст в каталог раздела.** Одна запись в `catalogue.items` файла `src/_data/catalogue/<раздел>.yaml` (образец — в `README.md` в той же папке). Чтобы текст появился на полке «Библиотеки» — строка в `shelf` этого раздела в `src/_data/sections.yaml`.

**Опубликовать новый перевод.** Данные текста — `src/_data/texts/<ключ>.json`; страница — копия `src/zacher-1.njk` (два десятка строк: шапка с `textKey`, `pageType: "reader"`, статусом, версией и карточкой `card`). Карточка на главной и блок «Опубликовано в разделе» появятся сами — по полю `card`.

**Добавить или изменить работу на странице «Исследования».** Отредактируйте `src/_data/studies.yaml` — одна запись на работу. Поля описаны в начале файла.

**Добавить раздел библиотеки.** Запись в `src/_data/sections.yaml`, данные в `src/_data/catalogue/<раздел>.yaml` и страница-заглушка по образцу `src/music.njk` (шапка и одна строка `{% include "section-body.njk" %}`).

**Добавить ссылку.** Внутренние ссылки — просто имя файла: `<a href="method.html#ai">`. Внешние — полный адрес.

**Убрать уведомление «Макет».** Удалите строку `mock:` в шапке страницы.

## Оформление: правила

- Цвета, кегли и отступы берутся только из переменных в начале `base.css` (`--ink`, `--fs-sm`, `--s4` …). Новых размеров шрифта и цветов в стилях страниц не заводим (в пунктах задан только кегль печати).
- Три ширины экрана, на которых меняется вёрстка: 640, 900 и 1200 пикселей. Других не вводим.
- Красный (киноварь) — слова источника (леммы), номера примечаний и помета «нет перевода». Синий (лазурь) — ссылки и статусы проверки.
- Повторяющийся блок — это деталь из `components.css` или макрос из `ui.njk`. В `pages/<страница>.css` остаётся только то, чего больше нигде нет (особый рисунок, таблица).
- Поведение (фильтры, переключатели, копирование, оглавление, поиск по списку, тема) включается атрибутами в разметке и живёт в `site.js`; список атрибутов — в начале этого файла.
- У читателя есть светлая и тёмная тема (кнопка в шапке) и печать: и то и другое проверяйте после правок стилей.

## Как сохранять правки

**Прямо в браузере.** Откройте файл на github.com → значок карандаша (Edit) → правка → **Commit changes** в `main`. Для нескольких файлов сразу нажмите `.` на странице репозитория: откроется редактор github.dev, там правки сохраняются одним коммитом.

**На своём компьютере.**

```bash
npm install
```

Предпросмотр с автообновлением, http://localhost:8080:

```bash
npm run serve
```

Затем сохраните правку и отправьте на GitHub:

```bash
git commit -am "Опечатка на странице «Метод»"
```

```bash
git push
```

Проверить сборку локально:

```bash
npm run build
```

```bash
npm run check
```

Сайт собирается в папку `site/`. Её можно открыть и прямо с диска: все ссылки относительные. Тему для проверки можно задать в адресе: `?theme=light` или `?theme=dark`.

Сообщение коммита — это запись в публичной истории правок страницы. Пишите его по-человечески: «Исправлена дата в примечании 17», «Статус статьи: проверено автором».

## Выкладка

`.github/workflows/deploy.yml` на каждый коммит в `main`:
1. собирает сайт;
2. копирует на сайт озвучку глав из выпусков GitHub;
3. проверяет все внутренние ссылки и якоря — при ошибке ничего не выкладывается;
4. публикует на **GitHub Pages**;
5. если настроено зеркало, копирует то же самое на него.

Ход сборки виден во вкладке **Actions** репозитория.

## Зеркало

Нужно для читателей, у которых GitHub или Cloudflare работают плохо. Подойдёт любой сервер с SSH и веб-сервером (nginx, Caddy), раздающим папку. Cloudflare перед зеркалом не ставить: из России его трафик режется.

В репозитории: **Settings → Secrets and variables → Actions**.
- Variables:
  - `MIRROR_HOST` — адрес сервера;
  - `MIRROR_USER` — пользователь;
  - `MIRROR_PATH` — папка, которую раздаёт веб-сервер, например `/var/www/neoscholia`;
  - `MIRROR_PORT` — если SSH не на 22.
- Secrets: `MIRROR_SSH_KEY` — приватный ключ, чей публичный ключ добавлен в `~/.ssh/authorized_keys` на сервере.

Пока `MIRROR_HOST` не задан, шаг зеркала пропускается. Второе зеркало добавляется копией задания `mirror` с другими переменными.
